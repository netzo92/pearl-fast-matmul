Pearl fast matmul

We’re testing whether miners can save work by choosing matrices whose useful product is zero. Grouping Pearl’s noise makes our M4 multiplication kernel faster. Complete mining cost is still unmeasured.

GPU results

At 2048 × 512, grouping takes about 17.3 ms per candidate instead of 22.2 ms: 28% more computations per second, or 22% less time. Smaller shapes show less benefit.

Conclusion

We have a faster local matrix kernel. We have not shown that useless mining is cheaper than adding mining to useful inference.

Pearl’s economic example assumes an existing inference provider pays 10% extra for mining. If our 1.28× kernel ratio carried over to the whole mining bill, useless mining would still cost about 78% of the reference bill: 7.8 times that assumed extra cost. Neither complete cost has been measured here.

ELI5

Someone already runs a machine for a customer. Collecting mining rewards costs them an extra $10. Another person runs the machine only for mining, normally costing $100. If our shortcut cut their whole bill to $78, they would still pay more than $10. Those are example dollars; the actual costs need measuring.

Calculation and assumptions

Method

The grouping identity

When raw B is zero, Pearl’s noise has the form V[p] − V[q]. Group terms that use the same V entry, then remove one coefficient per connected component. The example below reduces three multiplications to two.

1Signed selections

a(V₀ − V₁) + b(V₁ − V₂)
+ c(V₂ − V₀)

Start with three multiplications.

2Collect by vertex
G₀a − c
G₁b − a
G₂c − b

G₀ + G₁ + G₂ = 0

Every signed edge cancels in the sum.

3Choose an anchor
ANCHOR: V₀

G₁(V₁ − V₀)
+ G₂(V₂ − V₀)

3 products → 2 products

Each intermediate result stays the same.

General case

A chunk with r vertices and c connected components needs r − c grouped multiplications per output entry. Batch processing reuses the graph and grouped operands across tiles. Graph construction, additions, and memory traffic still cost time.
