01 / THE METHOD

Find the structure
inside the noise.

With the raw B matrix set to zero, its noised entries are signed differences of seeded values. Treat those selections as a graph, then combine their coefficients.

1Signed selections

a(V₀ − V₁) + b(V₁ − V₂)
+ c(V₂ − V₀)

Three products in this small example.

2Collect by vertex
G₀a − c
G₁b − a
G₂c − b

G₀ + G₁ + G₂ = 0

Every signed edge cancels in the sum.

3Choose an anchor
ANCHOR: V₀

G₁(V₁ − V₀)
+ G₂(V₂ − V₀)

3 products → 2 products

The result stays exact at every chunk.

IN THE FULL ALGORITHM

A chunk with r vertices and c connected components needs r − c grouped multiplications per output entry. Batch processing reuses the graph and grouped operands across tiles. Graph construction, additions, and memory traffic still cost time.

LOCAL GPU UPDATE

Reuse preparation.
Compute fresh candidates.

Fixed zero B, four distinct sparse A inputs per job. All three Metal paths match 178,257,920 reference intermediate values and 43,520 tile hash states across 32 fixtures. Every raw product AB is zero; changing A regenerates its noise and reference hashes.

28% more matrix-stage throughput at the largest shape.

At 2048 × 512 output, direct computation takes 22.15 ms per candidate versus 17.29–17.31 ms grouped, across two predetermined job keys. These times include per-candidate A grouping and B preparation shared across four candidates. All methods receive B reuse; an additional direct control includes per-candidate A packing. Ratios use the faster direct control. All eleven paired rounds favor grouping on both keys at this shape.

Smaller shapes show less benefit. Timed rounds replay the same finite candidate set. These local integer prototypes exclude commitments, noise generation, final state/hash computation and proof generation. No comparison against Pearl’s NVIDIA miner or total mining advantage is established. The next test compares complete useless-mining cost per reward with the extra cost of mining during useful inference; no predetermined speedup factor is required. Read the cost model.

CONCLUSION

What their estimate
would imply.

Pearl's economic example assumes a 10% extra mining cost for an existing inference provider. Even if our 1.28x matrix-stage ratio carried over to complete mining cost, dedicated useless mining would cost about 78% of the reference, roughly 7.8 times that assumed extra cost. That extrapolation is hypothetical; neither complete cost has been measured here.

ELI5

Imagine earning the same raffle tickets with two machines. One already works for a paying customer, so collecting tickets costs an extra $10. The other runs only for tickets and normally costs $100. If our shortcut reduced its whole bill to $78, it would still cost more than $10. These are illustrative dollars. We must beat the actual extra bill; a faster matrix stage alone does not settle that comparison.

Exact useless grouping works in our local checks. A competitive mining advantage and a break of Pearl's hardness conjecture remain unestablished. Read the conclusion and assumptions ↗
